# Performance evidence and explicit bounds

Run `python scripts/benchmark.py reports/benchmark.json` from an installed source checkout. The actual local output is [benchmark.json](assets/v2-final/benchmark.json). It records interpreter/platform/CPU, sample count, wall/process CPU time and Python traced-allocation peaks for decode/normalization, benign rules, state-pressure rules, per-packet durable SQLite and 32-observation transactions. Query samples use an authenticated in-process Flask client, not a network latency measurement. Queue stress offers260 observations to capacity128 and verifies132 visible drops.

These figures are offline generated metadata measurements. They are **not live capture PPS**, link capacity, complete RSS, zero-loss guarantees, or production appliance sizing. A single noisy workstation run is not a sustained load test. Per-packet durable commit is deliberately measured alongside batching to expose storage costs. Rule-state pressure demonstrates bounded evictions rather than hiding capacity loss.

Bounds: default2048 queue slots,4096 rule keys/SYN fingerprints/DNS baseline keys,512 observations/window,128 active partition clocks,256KiB metadata DTO,32-packet consumer transaction,50 UI rows,250 API maximum rows,20MiB/5000packet PCAP import,120s validation,100flow/action export records,100occurrences/alert,500 inline response transitions. Flows persist in SQLite, not an unbounded in-memory conversation map; disk grows until retention. Raw event/flow/bucket default7days; evidence default90days by ingestion time. Kernel loss is unknown; parser/writer failures, queue overflow, state evictions and window truncations are exposed.
